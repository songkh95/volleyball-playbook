# 배구 전술 보드 — 시작 계획

원본: 저장소 루트 `배구 전술 보드 시작 계획.txt`  
최종 정리: **2026-08-25**  
목표: Play Store + App Store (갤럭시, 아이폰)  
원칙: 로그인·서버 없음. 폰 앱과 PC 웹이 같은 코드, 같은 백업 파일.

이 문서는 **처음 만들 때 잠근 결정**이다. 그 뒤에 들어간 기능(3D, 자세, 경기 기록 등)은 [features.md](./features.md)를 본다.

---

## 0. 한 줄 요약

모바일 웹(Vite + React)을 먼저 만들고 Capacitor로 스토어에 올린다.  
데이터는 기기의 IndexedDB에 두고, 앱 삭제 전 백업 파일(`.vpb`)을 폰에 저장한다.  
재설치·컴퓨터 웹에서는 그 파일을 불러온다. 서버비 0원.

웹과 앱은 실시간 동기화가 아니다.  
PC에서 고치면 파일을 다시 저장한 뒤 폰에서 불러와야 한다.

---

## 1. 비용

- 서버 / DB / 로그인 / SMS: 없음
- 스토어: Google Play $25 1회 + Apple Developer 연 $99
- PC 웹 호스팅: Cloudflare Pages 등 정적 호스팅 (코드만 올림)
- iOS 제출: Mac + Xcode 필수 (Windows에서는 안드로이드·웹만 가능)

영상이 클라우드에 들어가면 단가가 무너진다.  
전술 JSON만 백업하고, 캡처·영상은 기기에만 둔다.

---

## 2. 백업 파일 (폰 + 웹)

iOS·안드로이드는 앱 삭제 순간을 가로챌 수 없다.  
UX는 “삭제하기 전에 백업 저장”이다.

1. 앱에서 [백업 저장] → 파일 앱 / 다운로드 / 드라이브 → `playbook-날짜.vpb`
2. 앱 삭제 → 앱 안 데이터는 사라짐. 파일은 그대로
3. 재설치 → [백업 불러오기] → 홈 전술 목록 복구
4. 파일을 PC로 옮긴 뒤 웹앱에서 [백업 열기] → 같은 전술

주의: `.vpb`를 더블클릭만 해서는 웹이 자동으로 켜지지 않는다.  
컴퓨터에서는 웹앱 주소에 접속한 다음 [백업 열기]로 파일을 고른다.  
파일은 서버로 업로드되지 않고, 브라우저가 PC 안에서만 읽는다.

| 종류 | 용도 |
|---|---|
| 전체 백업 `.vpb` | 전술 전부 (앱 삭제 전, PC 이동) |
| 전술 하나 `.vplay` | 선수에게 카카오·에어드롭 (계획. 구현 여부는 코드 확인) |

백업에는 갤러리(캡처·영상)를 넣지 않는다.  
불러오기: “현재 목록에 추가”와 “전부 교체” 둘 다. 덮어쓰기만 있으면 실수로 기존 전술이 날아간다.

## 5. 권장 스택 (당시)

한 벌의 앱: Vite + React + TypeScript  
UI: TailwindCSS  
코트: HTML Canvas + 포인터 이벤트  
일상 저장: IndexedDB  
백업: `.vpb` 저장 / 불러오기  
네이티브: Capacitor  
하지 않음: Supabase / Firebase / SMS / 소셜 로그인

---

## 6. 이 순서로 만든다

0. 뼈대 — Vite, 다크 셸, 홈/갤러리/에디터, IndexedDB
1. 코트 + 오브젝트 — 하프코트, 공+선수 드래그, 선수 편집 모달
2. 컷 + 보간 — 컷 추가/삭제, 슬라이더, 재생, 점선 궤적
3. 도구 + 프리셋 — 화살표 펜, 실행 취소, 구역, 대형
4. 백업 파일 — 저장 / 불러오기, 삭제 전 안내
5. 미디어 + 갤러리 — PNG 캡처, 전술 제목 폴더
6. 스토어 + 웹 주소 — Capacitor, 개인정보 페이지

체크리스트 완료 표시는 원본 txt 14~19절과 같다. 단계 6의 Play 내부테스트·iOS TestFlight는 당시 미완.

## 7. 데이터 모델 (당시 v1)

좌표는 코트 기준 0~1.  
하프/풀 전환 시 타임라인은 초기화.  
보간은 인접 컷의 x,y 선형 보간.  
선수 id는 전 컷 공통. 펜 선은 그 컷에만, 보간 없음.

```
Backup { schema, app: "volleyball-playbook", exportedAt, plays }
Play   { id, title, court: half|full, rosterSize: 6|9, cuts, updatedAt }
Cut    { id, durationMs, objects, strokes }
Obj    { id, kind: player|ball, x, y, label, color }
Stroke { points, color, arrowhead }
```

이후 스키마에 앨범, 프리셋, 경기 기록, 공 높이·비행, 선수 자세가 추가됐다. 현재 타입은 `src/types/play.ts`.

## 8. 코딩 전에 잠근 결정 (v1)

- 웹에서도 같은 에디터. 실시간 동기화 아님
- 백업 불러오기: 현재 목록에 추가 + 전부 교체
- 갤러리 백업 넣지 않음 (전술 JSON만)
- 선수 추가·삭제는 모든 컷에 동일
- 펜 선은 그 컷에만
- 화면 방향 세로 고정, 언어 한국어만
- 로그인·SMS 하지 않음

당시 “컷 길이 모두 1초, 배속 없음”은 이후 배속이 들어갔다.

## 13. 원기획 핵심 기능 (상세)

### 컷 기반 애니메이션

하단 타임라인, 컷 추가/삭제, 길게 눌러 순서 변경, 슬라이더 보간, 재생, 이동 궤적.

### 코트

프리존 없이 주황 플레이 코트.  
하프: 우리 팀 전체 + 상대 어택 라인.  
풀: 18m × 9m.  
구역 오버레이: 안함 / 6구역 / 9구역.

### 오브젝트

공 1개, 선수 터치 드래그, 선수 추가 무제한.  
탭하면 이름/포지션 라벨, 유니폼 색.

### 그리기

스마트 화살표 펜, 실행 취소, 이전 컷 복사, 첫 컷 리셋.

### 대시보드

상단 탭 [홈] [갤러리].  
새 전술 모달: 제목, 하프/풀, 6인/9인.  
`window.alert` / `confirm` 금지, 커스텀 모달만.
